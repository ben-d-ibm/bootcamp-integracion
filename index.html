Arquitectura Híbrida

Construye un workflow de transferencias bancarias que conecta una base de datos on-premise con IBM webMethods Integration en la nube, sin exponer tu red.

Arquitectura

¿Qué vamos a construir?

Un flujo end-to-end donde una app externa dispara un Webhook en IWHI SaaS, que consulta datos de cliente en un PostgreSQL local a través de un Edge Runtime en la misma red, evalúa el saldo con un Switch y devuelve una respuesta aprobando o rechazando la transacción.

El Edge Runtime se despliega dentro de la misma red Docker que PostgreSQL, permitiendo que IWHI SaaS consulte la base de datos on-premise sin abrir puertos en el firewall. El FlowService encapsula la query SQL y el Workflow orquesta la lógica de negocio completa.

Contexto

¿Por qué arquitectura híbrida?

Las organizaciones no pueden migrar todos sus sistemas a la nube de golpe. Los datos sensibles, los sistemas legacy y las regulaciones exigen que parte de la infraestructura permanezca on-premise. La integración híbrida resuelve este problema permitiendo orquestar flujos que cruzan ambos mundos de forma segura.

Datos sin exponer

La base de datos nunca abre puertos externos. El Edge Runtime establece una conexión saliente segura hacia IWHI SaaS, sin reglas de firewall inbound.

Orquestación en la nube

IWHI SaaS centraliza la lógica de negocio, las integraciones y el monitoreo, sin depender de un servidor de integración on-premise que mantener.

Escalabilidad incremental

Podés conectar múltiples runtimes en distintas redes (filiales, países, proveedores) sin cambiar la lógica del workflow central en la nube.
